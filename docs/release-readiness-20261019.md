## 正式上线顺序

1. 将本次修复纳入待上线提交，确认配套小程序构建和稳定的运维连接。先构建并准备新 Web 镜像，保存旧应用镜像作为恢复配套。
2. 安排停写窗口，停止旧应用与其他数据库写入者。停止后再取最新完整备份并校验，按 [迁移手册](content-model-migration-runbook.md) 在副本核验。此次副本结果不替代停写时的新备份。
3. 通过稳定数据库隧道设置生产 `DATABASE_URL` 和实际 `NEXT_PUBLIC_MEDIA_BASE_URL`，执行 `npm run db:migrate -- --archive-review /private/path/orphan-review.json`。指纹不符或发现新问题时中止并重新审核，禁止强写账本跳过。
4. 执行只读部署门禁、核对数量/引用/归档，再部署同一提交的 Web，并发布配套小程序。旧客户端与新数据协议不兼容，需协调发布与客户端刷新；不能用运行时兼容层规避。
5. 实际验证登录、素材修改同步、地图合集投放、Scene 保存与手机扫码手动放置、旧合集二维码、上传和识别。
6. 若失败，保持停写。当前迁移事务会回滚，但之前已成功的迁移仍保留；根据失败点继续修复迁移，或恢复完整升级前备份和旧应用。不能只回滚应用镜像连接已删列的新库。升级后有新增数据时，先保留新增数据，再决定恢复或前向修复。

推送 main 会触发部署；新增门禁会在生产库未迁移时主动阻止上线，不会自动执行破坏性迁移。当前演练证据保存在工作区父目录 `.local-db-backups/premerge-20261019/evidence/`；该目录不入 Git。
