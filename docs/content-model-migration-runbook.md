# 单一内容模型迁移

本分支只运行团队素材、场景和地图合集模型。`npm run db:migrate` 在一个事务内转换旧数据并移除旧结构，不再按组织选择模型，不需要请求头、激活接口或灰度开关。

## 数据转换

- 原 `workspace` 保留 UUID、名称、团队、标签和二维码上下文，成为地图合集。团队拥有素材和场景，合集只拥有投放。
- 旧素材转换为团队素材身份、不可变版本和资源清单。跨团队素材拆分为各团队独立身份；同一团队跨 workspace 的内容共享版本，但每个合集获得独立投放。
- 旧场景转换为 schema 3 草稿，模型引用固定到版本；已展示场景拥有发布快照和对应投放。已有新版草稿、版本和发布快照不重新生成。
- GPS、高度、标签、展示参数随投放迁移；文件地址进入版本资源清单。迁移快照中的嵌套展示信息转入投放，运行时不读取 `migration_legacy`。
- 匹配点使用素材版本和合集投放，特征向量绑定参考图版本。已有参考特征随对应版本保留。
- 已有明确隔离原因、无法判定团队归属的记录进入 `migration_archive`；未登记到版本的历史文件引用由 `storage_hold` 保留。未审核的无归属、无效场景或坐标异常会使整个事务失败，必须修复源数据后重试。
- 移除 workspace 成员授权、素材使用授权、旧公开 ID 映射和共享 scope 表；移除 Asset 原始内容字段、组织模型状态及旧写入函数。公开发现 ID 为 Placement ID。

## 执行

1. 对目标数据库做完整备份，并先在副本运行迁移。停止旧应用写入；本次升级包含删列和删表，旧应用不能继续连接升级后的库。
2. 使用目标数据库的 `DATABASE_URL` 和实际 `NEXT_PUBLIC_MEDIA_BASE_URL` 执行 `npm run db:migrate`。迁移不会上传或删除 OSS 文件。升级入口只有 `db:migrate`，分阶段切换和回切脚本已移除。
3. 检查迁移账本、合集数量、各合集投放、固定版本引用、资源清单及隔离归档，再部署本分支应用。
4. 验证团队素材创建、场景发布、合集投放、小程序发现、二维码和匹配点。新库直接使用 `db/schema.sql` 的最终结构。

迁移器持有数据库级迁移锁，并在同一事务内执行数据转换和 DDL。失败会整体回滚；已完成的迁移由 `schema_migrations` 跳过。成功之后需要回退时，应停写并恢复升级前备份及对应应用版本，不能重新启用旧模型写入。

## 验证脚本

`test-single-content-model-migration.ts` 使用 `scripts/test-support/pre-single-content-model.sql` 作为升级前快照，要求 127.0.0.1:55439 上全新的 `content_single_migration` 专用数据库。它验证失败回滚、跨团队拆分、合集独立投放、场景版本固定、标签、高度、资源、隔离保留和旧结构移除。

`test-content-model-services.ts`、`test-team-workbench-routes.ts` 在同一验证容器的 `team_wb_services` 数据库验证最终服务和无版本请求头的 HTTP 契约。测试不连接生产存储。
